## 一、存档结构（实测，非推测）

### 1.1 目录树

```
新的世界/
├─ level.dat            2423 B   gzip+NBT，世界全局数据（根标签 Data）
├─ level.dat_old        备份（写盘时游戏自动轮换）
├─ session.lock         3 B = U+2603 "☃" + 文件锁，用于判断游戏是否占用存档
├─ icon.png             存档图标
├─ region/              主世界地形区块  21 个 .mca
├─ entities/            主世界实体      16 个 .mca（1.17+ 实体已从地形区块剥离）
├─ poi/                 主世界兴趣点     7 个 .mca（村民床位/工作站/传送门）
├─ DIM-1/{region,entities,poi,data}   下界（维度 id: minecraft:the_nether）
├─ DIM1/{region,entities,poi,data}    末地（维度 id: minecraft:the_end）
├─ data/                raids.dat、random_sequences.dat
├─ playerdata/<uuid>.dat[._old]        玩家数据（单人模式下与 level.dat 内的 Player 双写）
├─ stats/<uuid>.json    统计
├─ advancements/<uuid>.json  进度
└─ datapacks/           空
```

### 1.2 region 文件（.mca / Anvil）格式要点

- 文件 = 4KiB 扇区序列。**前 2 个扇区（8KiB）是头**：
  - `[0,4096)` 定位表：1024 项 × 4B，`offset(3B, 扇区号) + sectors(1B)`，索引 `i = (x&31) + (z&31)*32`。
  - `[4096,8192)` 时间戳表：1024 × 4B（Unix 秒）。
- 每个区块体：`4B 长度(含压缩字节) + 1B 压缩方式 + 数据`，尾部按 4KiB 对齐补齐（补零不计入长度）。
- 压缩方式：1=gzip、2=zlib、3=不压缩、4=LZ4、127=自定义（数据存 `c.x.z.mcc`）。
  **本存档 10317 个地形区块全部为 2=zlib，无 .mcc 外置区块。**
- 单区块上限 255 扇区（≈1020KiB），超出转外置 `.mcc`。

### 1.3 区块（Chunk）NBT 关键字段（1.18+ 扁平化之后）

| 字段 | 含义 / 实测值 |
|---|---|
| `DataVersion` | 3955（= 1.21.1），**全存档统一，无混版本** |
| `xPos` / `zPos` | 绝对区块坐标（不是 region 内相对坐标） |
| `yPos` | 最低 section 的 Y，实测全为 -4（1.18 起世界高 -64~319 → 24 个 section） |
| `Status` | 生成阶段；**实测存在大量未完全生成的 proto-chunk**（见 1.6） |
| `sections[]` | 24 个，每节 `Y`(byte) + `block_states{palette,data}` + `biomes{palette,data}` + 可选 `BlockLight/SkyLight` |
| `block_states.palette` | 1.21.1 为**复合物列表**（`{Name, Properties}`），非 1.20.5+ 的字符串；索引按 `bits=max(4,ceil(log2 n))` 且**不跨 long 打包** |
| `block_entities[]` | 方块实体（箱子/刷怪笼/容器…），实测 4983 个 |
| `block_ticks[]` / `fluid_ticks[]` | 待触发的方块/流体更新（红石、流动水） |
| `structures{starts, references}` | 结构生成状态与跨区块引用 |
| `Heightmaps` | MOTION_BLOCKING / WORLD_SURFACE / OCEAN_FLOOR / MOTION_BLOCKING_NO_LEAVES，**9bit×256 打包于 long**，改方块后必须重算 |
| `InhabitedTime` | 玩家在该区块累计 tick，影响区域难度与刷怪 |
| `LastUpdate` | 上次保存的 tick |
| `isLightOn` | 光照是否已算（=0 会让游戏重算） |
| `PostProcessing` | 待更新的方块坐标（proto-chunk 转 full 时用） |
| `blending_data` | 1.18 地形混合数据 |

### 1.4 实体文件（entities/*.mca）

同一套 .mca 容器，NBT 根结构不同：

```
{ DataVersion: 3955, Position: [cx, cz], Entities: [ {id, UUID:[4×int], Pos:[3×double], Motion, Rotation,
                                                    Health, Air, Fire, Age, Item:{id,count,components}, ...} ] }
```

1.21.1 的物品是**组件化**格式：`{count, id, components?}`（旧版 `tag`/`Count`/`Damage` 已废）。

### 1.5 POI 文件（poi/*.mca）

```
{ DataVersion, Sections: { "<sectionY>" : { Valid:1, Records:[ {pos:[x,y,z], type:"minecraft:home", free_tickets:1} ] } } }
```

`type` 含 `home / meeting / <职业> / nether_portal / bee_nest / lodestone` 等。删房屋/搬迁村民后此处常残留孤立记录。

### 1.7 目标版本注意事项（1.21.1 特有）

- `playerdata/*.dat` **没有** `Data` 包裹（直接是玩家复合物）；`level.dat` 是 `Data` 包裹。
- 效果/属性字段已全部小写化（`active_effects`、`attributes` 的 `id/base/modifiers`）；
  `Lock`→`lock` 是 1.21.2 才改，1.21.1 仍是 `Lock`。
- `DataVersion` 若被改高，游戏会走数据升级器（不可逆），因此工具必须锁死 3955 且默认不改。
- 1.21.1 仍使用 `DIM-1` / `DIM1` 目录；**26.1 起改为 `dimensions/minecraft/...`**，工具需按版本分支。

## 四、环境备注（执行前需知）

1. **Rust 工具链已就位**：`rustc 1.99.1`（x86_64-pc-windows-gnu）+ cargo，装在工程内
   `.toolchain/`，走 `rsproxy.cn` 镜像拉 crates，链接器用 rust-lld（本机无 MSVC/MinGW gcc）。
2. **DSH 沙箱目前不允许写存档目录**（`workspace-write` 只覆盖 `D:\@工作区\存档管理器`）。
   开发期我会把存档复制进工作区做全流程验证；正式使用时由你自己运行 exe，或临时授权。
3. 目标存档 `session.lock` 处于被占用状态（游戏可能开过），**任何写操作前都会先做占用检测**。
